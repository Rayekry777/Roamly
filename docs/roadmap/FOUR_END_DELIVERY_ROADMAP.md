## 路线图职责

本文不是第五份产品契约，不定义字段、枚举、页面或数据库。它只协调后端、消费者小程序、商户小程序和管理 Web 的实施顺序与完成判定。

真源优先级固定为：运行时 OpenAPI 管 HTTP 线协议，[数据库契约](../../DATABASE_SCHEMA.md) 管持久化事实，各端开发契约管本端行为，本文管阶段依赖。阶段设计只能引用真源，不能复制后再产生第二套定义。

## 状态规则

- 阶段状态只使用“未实现、开发中、已实现”；外部设备或服务无法验证时在验收项单列“未确认”。
- 每阶段编码前必须具备已冻结的详细设计；变更接口、数据、权限、状态机、金额或验收时必须解冻、升版和重审。
- 一个阶段涉及的所有端、真实 HTTP、数据库与自动化均通过后才标记“已实现”；单端完成只更新对应端契约。
- 阶段 1-14 保持历史编号和已实现状态；未提交的旧阶段 15-19 文档直接替换，不保留编号兼容。

## 交付顺序

每阶段按“详细设计复核与冻结 -> 后端数据及接口 -> 对应客户端 -> 自动化 -> 真实运行时 -> 契约状态更新”的顺序推进。不得为赶前端进度返回假数据，也不得因服务端类已经存在跳过客户端和运行时验收。
