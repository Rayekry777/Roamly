## 目标

实现 12 位券编号的核销预览、确认、按次使用、误核销撤销和平台审计；动态二维码留到阶段 27。

## 设计复核（v2）

- 券号统一为 12 位数字，数据库保存展示用脱敏尾号与 HMAC-SHA256 索引；开发种子使用可重建的固定密钥生成索引。
- 预览令牌存 Redis 5 分钟并绑定门店、券、操作账号和消费金额；确认成功后立即消费，重复确认回查同一核销事实。
- 套餐、代金、折扣券一次核销，次卡每次扣减一次；券状态按剩余次数进入 `PARTIALLY_USED`（部分使用）或 `USED`（已使用）。
- 撤销只追加反向核销事实并恢复一次剩余次数，已结算记录禁止撤销；平台端仅按权限只读查询。

## 进入条件与涉及端

- 进入条件为阶段 25 已实现，店主、店长和核销员账号权限、门店绑定与停用会话已通过验收。
- 涉及后端、商户小程序和管理 Web；消费者端动态二维码在阶段 27 接入。

## 状态机、数据与权限

- 用户券从 `UNUSED`（未使用）进入 `PARTIALLY_USED`（部分使用）或 `USED`（已使用）；撤销恢复到与剩余次数一致的状态，已结算记录不可撤销。
- 新增 `voucher_redemption`，保存正向核销和显式撤销事实；券码索引、幂等键和约束以数据库契约为准。
- `OWNER`（店主）与 `MANAGER`（店长）可核销和撤销，`VERIFIER`（核销员）只可核销；管理端使用交易查看权限只读审计。

## 后端

- 新增 `voucher_redemption`；手输编号通过 HMAC 索引定位，不保存可用于批量枚举的裸索引。
- 预览校验门店、角色、券状态、有效期、星期、时段、排除日期和消费金额，但不修改券。
- 确认要求预览令牌和 `Idempotency-Key`，Lock4j 按券加锁，数据库状态更新取得唯一执行权。
- 套餐券一次核销；代金券和折扣券录入消费金额并返回抵扣结果；次卡每次默认扣减一次。
- `OWNER`（店主）和 `MANAGER`（店长）可撤销尚未结算的误核销并填写原因；`VERIFIER`（核销员）不可撤销。

## 接口

- `POST /v1/merchant/redemptions/previews/by-code`。
- `POST /v1/merchant/redemptions`、`POST /v1/merchant/redemptions/{id}/reversal`。
- `GET /v1/merchant/redemptions`、`GET /v1/admin/redemptions`、`GET /v1/admin/redemptions/{id}`。
- 跨店、不可用、重复核销和预览过期分别返回稳定错误码。

## 客户端

- 商户端手输编号后进入统一预览与确认页，明确展示门店匹配、规则、金额、次数和脱敏消费者。
- 成功页固定尺寸并禁用重复确认；撤销必须二次确认和填写原因。
- 管理 Web 提供核销、撤销、操作人、门店、券和审计筛选及详情。

## 失败处理

- 跨店、过期、退款中、时间规则不满足、预览过期和重复核销分别返回稳定错误，失败不得改变券状态。
- Lock4j 失败返回 409，Redis 不可用返回 503；数据库条件更新继续阻止重复核销。
- 撤销越权、超时或已进入结算返回 403 或 409，客户端刷新记录而不本地恢复次数。

## 验收

- 跨店、过期、时段、退款、并发、重复点击、次卡次数、撤销权限和已结算拒绝测试通过。
- 所有失败均不改变券和账本准备事实，成功与撤销审计完整。
- 商户端和管理 Web 自动化、真实 HTTP/OpenAPI 通过。
