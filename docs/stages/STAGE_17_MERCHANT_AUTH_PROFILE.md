## 目标

建立独立商户认证域和账号状态查询，交付商户小程序登录、会话恢复与“我的”状态页，不提前实现入驻表单。

## 进入条件与涉及端

- 进入条件为阶段 16 已实现，三类认证域的隔离方式、短信端口和错误结构已经通过真实运行时验证。
- 涉及后端与商户小程序；消费者小程序和管理 Web 不新增页面或接口消费。

## 状态机、数据与权限

- 商户账号展示状态只允许 `NOT_APPLIED`（未入驻）、`PENDING`（审核中）、`ACTIVE`（已激活）、`REJECTED`（审核未通过）、`DISABLED`（已停用），状态来源为服务端当前身份。
- 本阶段新增 `merchant_account`，但不写入驻业务资料；表结构和约束以数据库契约为准。
- 未激活账号只有认证、当前身份和后续入驻访问能力；已激活权限由 `OWNER`（店主）、`MANAGER`（店长）、`VERIFIER`（核销员）角色确定。

## 后端

- 新增 `merchant_account`，手机号唯一；未激活账号允许 `shop_id` 为空，激活账号必须绑定一家门店。
- 商户使用 `MERCHANT`（商户端）Sa-Token，Redis 键空间、拦截器和当前身份与消费者、管理员完全隔离。
- 复用短信端口和发送限流；dev/test 使用 `MOCK`（模拟），prod 无供应商时为 `DISABLED`（禁用）。
- 当前身份返回字符串 ID、脱敏手机号、昵称、头像、角色、账号状态、门店摘要和权限集合。

## 接口

- `POST /v1/merchant/auth/sms-codes`、`POST /v1/merchant/auth/login`。
- `GET /v1/merchant/auth/me`、`POST /v1/merchant/auth/logout`。
- 状态为 `NOT_APPLIED`（未入驻）、`PENDING`（审核中）、`ACTIVE`（已激活）、`REJECTED`（审核未通过）、`DISABLED`（已停用）。

## 商户小程序

- 初始化登录、Store、请求适配、状态守卫和“我的”；头像右侧展示五种中文状态。
- 未激活账号只允许登录、退出、当前身份和后续入驻路由；经营导航重定向到“我的”。
- 401 清理商户会话，403 保留页面并显示真实原因，短信 429 显示剩余等待。

## 失败处理

- 短信发送、验证码错误、频率限制和供应商不可用分别保留 400、429、503 语义，不回退消费者登录接口。
- 停用账号立即拒绝经营访问并清理商户会话；Token 域错误统一返回 401，不尝试跨端恢复。
- 当前身份结构异常显示契约错误，不能生成默认门店或伪造激活状态。

## 验收

- 三类 Token 互斥、短信限流、五种状态映射、停用会话和跨账号隔离测试通过。
- 商户小程序自动化覆盖登录、恢复、退出、所有状态和错误反馈。
- 真实 HTTP/OpenAPI 与微信开发者工具流程通过后标记“已实现”。
