# 阶段 41：三端退款与客服体验重构

状态：已实现
日期：2026-09-12

## 目标与边界

本阶段把阶段 39、40 已实现的退款与客服权威接口落实到管理 Web、消费者小程序和商户小程序。退款审核、Mock 执行、客服状态转换和权限仍由服务端决定；SSE/WebSocket 断开、连接或重连只触发刷新，不能写入业务状态。

不接真实支付、退款或结算，不新增外卖入口，不修改数据库结构，不执行未知开发数据库初始化。

## 冻结体验

- 管理端退款工作台按待审核、等待执行、处理中、失败、人工处理、部分退款、已完成和已拒绝分类，详情展示逐券明细、审核/执行状态、失败原因和时间线。
- 管理端客服工作台采用队列、会话、业务上下文三栏结构，支持认领、公开回复、内部备注、游标加载、附件、快捷回复、状态转换、标签和转交。
- 消费者端提供工单列表、创建、会话、图片附件、未读数、关闭和重新打开；订单与退款详情可带关联 ID 进入客服。
- 商户端提供本人主动创建工单的列表、创建、会话和附件；售后详情展示审核、Mock 执行、逐券明细和时间线，并可创建关联退款工单。
- 所有业务 ID 在三个客户端均保持字符串；金额由整数分格式化，不以订单交易状态推断退款进度。

## 必要接口补充

- `POST /v1/users/me/customer-service/tickets/{id}/closure`
- `POST /v1/users/me/customer-service/tickets/{id}/reopening`
- `GET /v1/admin/customer-service/tickets` 增加 `queue` 筛选，支持 `UNCLAIMED/MINE/SLA_BREACHED/HIGH_PRIORITY/REFUND`。

## 验收

- 三端状态展示以退款审核/执行与客服状态字段为准。
- 管理端能完成退款审核、拒绝、失败重试以及客服认领、回复、备注、转交和关闭。
- 消费者与商户只能看到本人主动创建的工单和公开消息。
- 附件通过各登录域的私有接口读取，内部备注附件不向申请人展示。
- 实时连接状态变化不修改退款或客服状态。
- 管理 Web、消费者小程序、商户小程序类型检查、Lint、测试和构建通过。
