# 阶段 12：商户详情与位置距离契约

状态：开发中
更新时间：2026-09-03

本阶段冻结商户详情的基础资料与位置语义。团购商品、点评和探店动态保留为已存在的独立资源，客户端按页面可见区域延迟请求，避免详情首屏被无关集合阻塞。

## 1. 最终 HTTP 契约

| 项目 | 最终定义 |
|---|---|
| operationId | `getShop` |
| 方法与内部路径 | `GET /v1/shops/{shopId}` |
| 外部生产路径 | `GET /api/v1/shops/{shopId}`，Nginx 剥离 `/api` 后转发 |
| 鉴权 | 公开 |
| 请求 DTO | 无请求体、无 DTO |
| 成功响应 | `200 Result<ShopVO>` |
| ID | 路径和 JSON ID 均为字符串；Service 内部使用 `Long` |

路径参数 `shopId` 为正整数字符串。可选查询参数：

| 参数 | 类型 | 规则 |
|---|---|---|
| `longitude` | number | 必须与 `latitude` 一起提交，范围 -180～180 |
| `latitude` | number | 必须与 `longitude` 一起提交，范围 -90～90 |

`ShopVO` 是稳定基础资料模型：ID、名称、分类、图片、商圈、地址、商户坐标、人均（元）、销量、点评数、放大 10 倍的评分、营业时间与可空 `distance`。字段含义、示例和范围已在 `ShopVO` 的 OpenAPI Schema 中逐项声明。请求提供完整坐标时，`distance` 为米；未提供时为 `null`。

## 2. 页面资源边界

商户详情页使用以下独立契约，不能在 `getShop` 中隐式额外查询或返回：

| 区域 | 接口 | 加载策略 |
|---|---|---|
| 基础资料、地址、营业时间 | `GET /v1/shops/{shopId}` | 页面首屏 |
| 团购与优惠 | `GET /v1/shops/{shopId}/voucher-products` | 区域进入视口后 |
| 到店点评 | `GET /v1/shops/{shopId}/reviews` | 点击全部点评页后 |
| 相关探店动态 | `GET /v1/shops/{shopId}/posts` | 区域进入视口后 |

这样首页可先绘制商户信息；每个子资源独立处理加载、空态与失败重试，也避免单一详情接口混合不同分页模型。

## 3. 错误码、缓存与实现

- `SHOP_NOT_FOUND`（404）：商户不存在或经营状态不是启用。
- `INCOMPLETE_COORDINATES`（400）：仅提交经纬度其中之一。
- `INVALID_COORDINATES`（400）：坐标超出有效范围。
- 商户基础记录继续使用既有穿透保护缓存；请求距离只在从缓存取出的基础记录副本上计算，不写回 Redis。
- 距离采用 Haversine 球面公式并返回米，不引入位置历史、隐私画像或用户位置持久化。
- 无事务、异步消息和幂等写操作；本阶段不修改 SQL 快照。
