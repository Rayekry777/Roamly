## 1. 实现范围

阶段 5 完成小程序社区入口从旧 Blog 形态向 Post 形态的页面迁移，覆盖五入口导航、首页双信息流与动态卡片、统一发布器及临时媒体交互。分区详情的信息流后端、Threads 评论和旧页面退役属于后续阶段。

已实现：

- 自定义底部导航固定为“首页 / 分区 / 发布 / 附近 / 我的”，发布保持中央操作按钮。
- 首页提供推荐与关注独立状态、横向分区入口、游标缓存、滚动恢复和列表 ID 去重。
- `post-card` 按作者、正文、媒体、分区、互动和热门评论顺序展示。
- 点赞和关注使用乐观更新，失败只回滚对应状态。
- 统一发布器支持普通动态与探店开关、分区和商户条件选择、最多 9 张临时媒体及草稿恢复。
- 普通动态请求不提交隐藏的 `sectionId`、`shopId`；探店动态只提交字符串 ID。
- 发布成功清空草稿并刷新推荐首屏；失败保留草稿并定位服务端校验字段。
- 分区列表提供匿名浏览、登录后关注、失败回滚和登录后意图恢复。
- 分区详情客户端同时完成最新/热门独立游标、滚动恢复和“漫游日常”城市切换，为阶段 6 后端信息流联调做好准备。

## 2. 契约边界

- 小程序业务 API 继续只声明 `/v1/**`，环境配置负责生产 `/api` 前缀。
- 媒体 URL 只通过 `assetBaseUrl` 解析，不附加 `/api`。
- 所有业务 ID 在 TypeScript 中保持 `string`，不得转为 JavaScript `number`。
- 首页不逐条请求评论或商户，热门评论和分区摘要由后续信息流接口直接返回。
- 旧 `package-blog` 暂时保留，等阶段 11 完成客户端和后端全量切换后统一移除。
