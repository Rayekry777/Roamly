```yaml
designVersion: 1
```

## 目标

完成四份契约职责拆分，建立阶段 15-30 路线图，并把管理 Web、商户小程序准备为独立工程。消费者现有功能只做契约和视觉复核，不改变业务行为。

## 进入条件

- 阶段 1-14 的代码、数据库和消费者自动化结论可追溯。
- 四个工作目录中的用户改动均保留，不回退未提交源码。

## 涉及端

- 后端负责根契约、数据库契约、若依适配决策、路线图与阶段设计归档。
- 消费者小程序只复核现有契约、README 和 Roamly 视觉真源，不改业务行为。
- 商户小程序与管理 Web 分别建立独立工程边界、README、契约和版本控制规则。

## 接口、状态机、数据与权限

- 本阶段不新增或修改 HTTP 接口、业务状态机、数据表、角色或权限码。
- 运行时 OpenAPI、数据库契约和四份端契约的真源优先级必须写入路线图；阶段文档只能引用，不能另建字段定义。
- 阶段 1-14 的实现状态不因文档搬迁改变；阶段 15 只有工程基线也完成后才能变为“已实现”。

## 交付

- 后端契约只管理服务端；三个客户端契约分别只管理本端页面、交互和接口消费。
- 管理 Web 固定 `plus-ui v5.6.2-v2.6.2` 来源、MIT License、第三方声明、Node 24 和 pnpm 11。
- 商户小程序初始化独立 Git、原生 TypeScript、TDesign、测试和微信项目配置，不复制消费者业务页面。
- 三个 UI 端分别固化 Roamly 颜色、字体、间距、圆角和状态样式；竞品截图仅记录为流程参考。
- 建立 OpenAPI 类型检查策略：后端运行时文档是线协议真源，各端拥有自己的 TypeScript 类型和适配器，不共享源码包。

## 边界

- 本阶段不新增业务接口、表或权限，不升级后端依赖，不实现管理员或商户页面。
- 路线图只记录顺序，不复制 DTO、状态机、数据库字段和页面规格。
- `.idea`、本地密钥、真实 AppID 和 `.env` 不进入版本控制。

## 失败处理

- 发现链接失效、版本来源不可追溯、契约职责重叠或阶段状态冲突时，冻结检查失败并保持“未实现”。
- 独立仓库初始化、许可证或基础验证缺失时，不以“文档已完成”替代工程交付。
- 竞品或若依视觉残留进入任一 UI 基线时，必须在本阶段清理并重新执行视觉令牌扫描。

## 验收

- 四份契约版本、职责、链接、阶段表和状态一致，无跨端页面或事务定义。
- 管理 Web 与商户小程序均为独立 Git 工程，README 与实际状态一致。
- 三端视觉令牌扫描通过，若依 Logo、默认蓝色和竞品视觉不在目标设计中。
- 四个工作区执行格式与链接检查，阶段 15 状态更新为“已实现”后才进入阶段 16。
