# Roamly 数据库表结构与开发数据说明

> 更新时间：2026-09-13  
> 数据库：MySQL 8.x / InnoDB / utf8mb4  
> 当前业务表：51 张  
> 结构真源：`ray-server/src/main/resources/schema-init.sql`  
> 开发数据真源：`ray-server/src/main/resources/seed-dev.sql`

## 文档定位

本文保存当前数据库的长期结构说明、逻辑关系、隔离范围、重要索引、初始化顺序和开发测试数据，不记录开发阶段、旧版目标表数或历史验收过程。

完整字段类型、默认值和索引名称以 `schema-init.sql` 为准；本文用于理解和维护，不复制完整 DDL。

## 总体规则

- 不使用 Flyway 或 Liquibase。
- 新环境使用完整 `schema-init.sql` 建表，再按 Profile 决定是否执行 `seed-dev.sql`。
- `schema-init.sql` 包含 `DROP TABLE IF EXISTS`，只允许用于明确可重建的 Demo 开发库。
- 已有数据或生产数据库禁止直接执行完整初始化脚本。
- 当前表不声明物理外键，跨表完整性由 Service 事务、行锁、唯一约束和权限校验维护。
- 金额统一使用整数分，费率统一使用基点 `bps`。
- Java 内部业务 ID 使用 `Long`，HTTP/OpenAPI 业务 ID 使用字符串。
- 时间字段存数据库时间事实，页面按 `Asia/Shanghai` 展示和切分自然日。
- 追加式账本和审计表不通过覆盖历史行表达撤销。

## 账号与治理表细节

### `admin_user`

核心字段：

- `username`：不可变登录名，唯一；
- `password_hash`：BCrypt 摘要；
- `display_name`：界面名称；
- `role`：固定管理员角色；
- `status`：`ACTIVE/DISABLED`；
- `force_password_change`：是否强制首次改密；
- `login_fail_count/locked_until`：登录失败锁定；
- `last_login_time`：最后登录时间；
- `version`：账号治理乐观锁。

最后一个活动平台超级管理员不能被停用。

### `merchant_account`

核心字段：

- `phone`：登录手机号，唯一；
- `password_hash`：BCrypt 摘要；
- `nickname/avatar_media_id`：个人资料；
- `role`：`VISITOR/TENANT/MANAGER/VERIFIER`；
- `status`：入驻和启停状态；
- `shop_id`：活动租户和员工所属门店；
- `disabled_source/disabled_reason/disabled_at`：停用来源和事实；
- `version`：资料与状态并发控制。

门店停用只恢复 `disabled_source=SHOP_SUSPENSION` 的账号，不能覆盖员工管理或平台治理停用。

### `merchant_application`

保存：

- 申请账号和申请状态；
- 门店名称、统一社会信用代码和法定代表人；
- 联系人、手机号、分类、城市、区县、地址和坐标；
- 七日营业时间 JSON；
- 营业执照和经营图片；
- Mock 结算户名、银行名和账号后四位；
- 提交幂等键；
- 审核决定、审核人、原因和时间；
- 审核通过后创建的门店 ID；
- 请求指纹和版本。

草稿允许不完整，提交时统一校验完整性。

### `business_media_asset`

用途：

```text
LICENSE
GALLERY
VOUCHER_COVER
VOUCHER_DETAIL
MERCHANT_AVATAR
```

生命周期：

```text
TEMPORARY → BOUND → DELETED
```

对象键唯一。绑定时必须校验上传者、用途、目标业务、数量限制和临时有效期。

## 社区与地域表细节

### 城市和区县

- `city.code` 是城市隔离编码。
- `district.city_code` 关联所属城市。
- 区县保存中心经纬度和服务半径，用于把真实坐标解析为区县。
- 当前没有物理外键，应用必须校验区县所属城市。

### `post`

保存作者、内容类型、分区、门店、城市、区县、粗粒度位置、计数和状态。城市参与硬隔离，区县和距离参与推荐排序。

动态媒体通过 `post_media` 保存有序关系，点赞和评论计数必须与关系表事实一致。

### 评论

- 根评论和回复统一在 `post_comment`。
- `root_id` 表示讨论根，`parent_id` 表示直接回复目标。
- 有有效回复的根评论删除后保留占位，避免讨论树断裂。
- 评论点赞由 `post_comment_like` 唯一关系保证防重。

### 点评

- `shop_review` 通过 `shop_id + user_id` 限制每个消费者每店一条有效点评。
- 消费认证点评保存关联核销事实。
- `shop_review_media` 保存有序图片。
- 门店点评数和评分由有效点评聚合重算。

## 商品表细节

### `voucher_product`

核心范围：

- 门店、标题、副标题、券型和审核状态；
- 销售状态、销售开始和结束时间；
- 原价、售价、平台优惠和商家补贴；
- 总库存、可售库存、已售数量和单人限购；
- 有效期模式、固定日期或购买后有效天数；
- 每周可用时段、不可用日期、预约和叠加规则；
- 随时退、过期退规则；
- 封面、版本、提交和审核事实。

审核状态和销售状态必须分别判断。`APPROVED` 只表示审核通过，不一定表示当前正在销售。

### 四类券专属表

- `voucher_package_item`：套餐服务项目、数量、单位和顺序；次卡也复用项目说明。
- `voucher_product_cash_rule`：代金金额和使用门槛。
- `voucher_product_discount_rule`：折扣展示信息，不参与平台订单计价。
- `voucher_product_multi_use_rule`：总次数和使用说明。
- `voucher_product_detail`：统一详情分段。
- `voucher_product_tag`：统一图标键和短标签。

专属表由 `product_id` 逻辑关联商品，Service 必须拒绝券型和专属规则不匹配。

## 订单、支付和券表细节

### `voucher_order`

保存：

- 用户、门店、商品、订单号和购买数量；
- 商品、门店、标题和价格快照；
- 原价、优惠、应付和实付金额；
- 交易状态和独立售后聚合状态；
- 支付截止时间、支付和退款时间；
- 创建幂等键、请求指纹和版本。

交易状态：

```text
PENDING_PAYMENT / PAID / CANCELED / COMPLETED
```

旧 `REFUNDING/REFUNDED` 仅兼容历史读取，新退款流程写 `after_sale_status`。

### `payment_transaction`

每次支付准备或确认形成独立尝试，保存：

- 订单、用户、金额和支付提供方；
- 商户支付单号、渠道流水号；
- 支付状态和失败原因；
- 幂等键、开始和完成时间。

支付成功后才按数量发券。重复确认由订单状态、幂等键和唯一约束共同拦截。

### `user_voucher`

保存：

- 用户、订单、订单内序号、商品和门店；
- 券码、HMAC 摘要和后四位；
- 总使用次数和剩余次数；
- 单券商品售价、商家补贴、平台补贴和顾客实付分摊；
- 有效期、使用时间、退款时间和状态。

同一订单按购买数量使用 `order_id + sequence_no` 唯一，不是 `order_id` 单列唯一。

### `user_voucher_qr_code`

- 每张券一条固定记录；
- `token_key` 为随机定位值，不保存完整明文二维码 Token；
- `token_version` 支持主动换码；
- 有效期沿用用户券；
- 服务端校验二维码签名、券归属、状态和有效期。

### `voucher_redemption`

除核销人、门店、方式、次数和状态外，保存不可变财务快照：

- 商品售价；
- 商家补贴；
- 平台补贴；
- 顾客实付；
- 服务费基数；
- 服务费率；
- 服务费；
- 商家预计收入。

历史商品或费率变更不能修改已生成快照。

## 退款、账本和结算表细节

完整状态、计算和失败恢复见[退款客服与资金结算业务细节](退款客服与资金结算业务细节.md)。

### `voucher_refund`

保存申请级聚合事实：

- 订单、用户、门店和第一张券兼容投影；
- `source` 和 `applicant_id`；
- 申请金额、批准金额和原因；
- 退款聚合状态；
- 审核状态、审核人、说明和时间；
- 执行状态、处理人、失败信息和重试次数；
- 渠道退款号和原支付渠道；
- 客服工单关联、幂等键和版本。

券集合以 `voucher_refund_item` 为准，不能解析兼容投影推导多券范围。

### `voucher_refund_item`

每张目标券一行，保存：

- 券和订单明细；
- 是否已核销；
- 商品售价、顾客实付、平台补贴和商家补贴；
- 原服务费；
- 可退金额和实际退款金额；
- 明细状态；
- 商家收入净冲回和服务费返还快照。

`refund_id + voucher_id` 唯一，阻止同一申请重复加入相同券。

### `voucher_refund_attempt`

保存每次渠道执行的：

- 退款和可选逐券明细 ID；
- 渠道幂等键；
- 执行状态和请求金额；
- Mock 场景和渠道退款号；
- 失败码、失败原因和重试次数；
- `lease_owner/lease_until`；
- `next_retry_at`、开始时间和完成时间。

队列索引覆盖状态、下次重试、租约截止和 ID。领取使用条件更新，只有一个 Worker 获得有效租约。

### `commission_rule`

- `shop_id=NULL` 表示平台默认规则；
- 非空表示门店覆盖规则；
- `rate_bps` 保存基点；
- `effective_from/effective_to` 保存生效区间；
- 核销按发生时间查询规则并将结果写入核销快照。

### `fund_ledger_entry`

核心字段：

- 门店、订单和券；
- `business_event_id`；
- `entry_type`；
- `account_side`；
- 可正可负的金额；
- 费率和服务费基数快照；
- 发生时间。

唯一约束：

```text
business_event_id + entry_type + account_side
```

该约束保证同一业务事件的同类分录不会重复写入。

### 结算表

- `settlement_batch`：每个门店每天一个批次，保存状态、总额、失败原因和完成时间。
- `settlement_item`：逐条关联账本，批次和账本组合唯一。
- `settlement_attempt`：保存 Mock 执行、幂等键、渠道引用及预留的租约和重试字段。

当前结算为同步 Mock；不能因为 `settlement_attempt` 有租约字段就认为已经实现异步结算 Worker。

## 客服表细节

### `customer_service_ticket`

核心字段：

- 工单号、类型、状态和优先级；
- `applicant_type + applicant_id`；
- 关联用户、门店、订单、券、退款和核销；
- 主题和描述；
- 当前客服；
- 首次/最近响应时间；
- 等待消费者/商户起点；
- 解决、关闭和可重开截止时间；
- 最后消息时间、SLA 截止和超时标记；
- 内部备注标记和版本。

外部权限真源只有 `applicant_type + applicant_id`。`user_id/shop_id` 是兼容字段，不能用于扩大查询范围。

### `customer_service_message`

- `sender_type/sender_id` 保存发送者；
- `visibility=PUBLIC/INTERNAL` 控制外部可见性；
- `message_type` 保存文本、图片、附件或系统消息；
- 消息按工单和 ID 游标读取。

内部备注和内部系统消息不能返回消费者或商户。

### `customer_service_attachment`

保存工单、消息、上传者、对象存储位置、原文件信息、大小和生命周期。临时附件必须在有效期内由同一登录域绑定；读取时重新校验工单和消息可见性。

### `customer_service_read_cursor`

唯一键：

```text
ticket_id + reader_type + reader_id
```

推进游标使用数据库 `GREATEST`，旧请求不能让已读位置倒退。

### 标签、转交和快捷回复

- 标签编码唯一；工单和标签组合唯一。
- 转交历史只追加，记录原客服、新客服、操作人、原因和时间。
- 快捷回复分 `PERSONAL/TEAM`，个人模板绑定所有者，删除使用停用状态。

## 数据一致性检查

- 动态点赞数等于 `post_like` 有效行数。
- 评论点赞数等于 `post_comment_like` 有效行数。
- 门店点评数和评分等于有效点评聚合。
- 待支付订单占用库存；关单只返还一次。
- 已支付订单按数量生成用户券；未支付或取消订单不发券。
- 用户券单券金额之和等于订单金额，除不尽余数归最后一张。
- 核销预计收入等于顾客实付加平台补贴再减服务费。
- 同一业务事件的同类账本分录只有一条。
- 退款金额不超过逐券可退金额。
- 未核销退款不产生核销收入冲回和服务费返还。
- 结算批次金额等于全部 `settlement_item.amount` 之和。
- 客服已读游标只前进。
- 外部申请人不能读取内部消息和附件。
