# 计费、补贴与结算计算细节

更新日期：2026-09-13。本文描述当前实现；计费规则变更时优先更新本文，再同步各端展示说明。退款审批、执行重试、客服和批次结算流程见 [退款客服与资金结算业务细节](退款客服与资金结算业务细节.md)。

## 1. 金额与承担方

金额在接口、数据库和后端中均以人民币整数分表示；页面输入和展示为元。业务 ID 通过接口传字符串。

| 名称 | 字段 | 含义 |
|---|---|---|
| 券售价 | price_amount | 单份实际销售价；次卡为整张卡售价 |
| 门市价/划线价 | market_amount | 展示对照，不参与实付或服务费计算 |
| 商家补贴 | merchant_subsidy_amount | 商家自担的每份活动优惠，减少商家应收 |
| 平台补贴 | platform_discount_amount | 平台替用户承担的每份优惠，减少用户实付，核销时补入商家应收 |
| 用户实付 | pay_amount / customer_paid_amount | 用户实际需要支付的金额 |
| 服务费 | service_fee_amount | 从商家核销应收中扣除的平台服务费用 |
| 商家预计收入 | estimated_income_amount | 核销确认的商家净收入，尚不代表银行实际到账 |

平台补贴不是额外奖励商家的经营补助。联合优惠按两方字段分别承担，不能把平台补贴再次扣到商家头上，也不能把商家补贴重复扣除。

## 2. 设置入口与权限

- 商家端：团购券 → 编辑 → 价格 → 活动优惠，填写每份商家补贴。平台补贴只读。沿用草稿/驳回可编辑、提交审核后锁定的流程。
- 管理端：团购券审核 → 详情 → 活动优惠，设置每份平台补贴。要求 `admin:voucher:review` 权限。
- 用户端：独立确认订单页和商品购买弹层都在“活动优惠”中展示合计，展开分别显示商家补贴和平台补贴。零金额明细不显示；合计为零显示暂无活动优惠。独立“优惠券”抵用占位已删除。

单份补贴范围为 0–100000000 分，填 0 取消；两方补贴合计不得超过售价。商家更新请求不接收平台补贴，保存时从锁定商品读取平台金额参与校验。复制商品保留商家补贴，平台补贴归零，由平台重新设置。

平台设置接口：`PUT /v1/admin/voucher-reviews/{productId}/platform-subsidy`。

```json
{"version": 3, "platformDiscountAmount": 500}
```

成功返回 200；非法参数 400、未登录 401、权限不足 403、商品不存在 404、版本冲突 409。使用行锁、商品版本和操作审计，记录原金额与新金额。仅修改商品配置，已有订单和用户券快照不变。

## 3. 下单实付

设单份售价 P、商家补贴 M、平台补贴 D、购买数量 Q：

```text
商品总价 = P × Q
商家补贴合计 = M × Q
平台补贴合计 = D × Q
用户实付 = (P − M − D) × Q
```

后端确认订单与创建订单均进行计算和校验；前端只展示接口返回值，不自行重算实付或重复抵扣。确认页返回的是数量合计，前端不得再乘一次数量。确认订单不占库存，创建订单重新校验当前价格和可售条件。

订单保存创建时的售价、补贴和实付快照。支付后按购买数量发券，用户券保存各自金额快照。补贴设置变化影响之后创建的订单，不改变已创建但尚未支付的订单金额。

## 4. 服务费与费率

普通单次券在核销时确认服务费：

```text
商家毛应收 = 用户实付 + 平台补贴 = 券售价 − 商家补贴
服务费基数 = max(0, 券售价 − 商家补贴)
服务费（分）= 服务费基数（分）× rate_bps / 10000
商家净收入 = 商家毛应收 − 服务费
```

整数除法直接截断不足 1 分的部分，不采用四舍五入。5% 表示 500 bps，1 bps = 0.01%。例如计费基数74.90元、费率5%，服务费为3.74元。

核销时按以下顺序选择费率：

1. 核销时刻生效的门店规则。
2. 核销时刻生效的平台默认规则（shop_id 为空）。
3. 均不存在时使用代码默认500 bps，即5%。这不是行业统一费率。

规则有效范围为 `effective_from <= 核销时间 < effective_to`，结束为空表示没有结束时间；同范围按开始时间、ID 倒序取一条。规则在核销时取值，不是在下单时锁定。核销保存实际费率、基数、费用及净收入，后续修改不重算已发生的核销。

商品优惠配置不允许合计超过售价；服务费基数的 max(0, ...) 是计算保护，不表示允许非法优惠配置。

## 5. 完整示例

| 项目 | 一份券 | 两份券 |
|---|---:|---:|
| 售价合计 | 100.00元 | 200.00元 |
| 商家补贴合计 | 10.00元 | 20.00元 |
| 平台补贴合计 | 5.00元 | 10.00元 |
| 用户实付 | 85.00元 | 170.00元 |
| 商家毛应收 | 90.00元 | 180.00元 |
| 服务费（5%，全部核销） | 4.50元 | 9.00元 |
| 商家净收入 | 85.50元 | 171.00元 |

单份券平台收4.50元服务费、支出5元补贴，未考虑支付通道和其他成本时净支出0.50元。服务费收入不能直接当作利润。

## 6. 多份券与次卡分摊

通用分摊函数为整数均分，余数全部放在最后一份/最后一次。例如1000分分三份为333、333、334分。优先使用用户券自身快照；缺失时才按订单数量及券序号从订单金额分摊。

次卡每次核销分别分摊整张券的售价、商家补贴、平台补贴和用户实付。服务费采用：

```text
整张券费用 = 整张券计费基数 × 当次核销适用费率 / 10000
当次服务费 = splitPart(整张券费用, 总次数, 当次成功核销序号)
当次净收入 = 当次用户实付分摊 + 当次平台补贴分摊 − 当次服务费
```

不能直接用“当次计费基数 × 费率”替代上述算法，否则会产生分摊尾差。核销记录中的 service_fee_base_amount 是本次分摊售价减本次商家补贴。

费率保持不变时，全部核销的费用相加等于整张券费用。当前实现每次核销重新选择生效费率；若次卡使用期间费率变化，各次核销可能采用不同费率，不能声称整张次卡费用在首次购买或首次核销时已经锁定。

## 7. 账本、撤销与退款

| 事件 | 资金含义 |
|---|---|
| REDEMPTION_RECOGNIZED | 确认用户实付加平台补贴组成的商家毛应收 |
| SERVICE_FEE_RECOGNIZED | 扣除本次核销服务费 |
| REDEMPTION_REVERSED | 撤销原核销毛应收 |
| SERVICE_FEE_REVERSED | 撤销时返还原服务费 |
| REFUND_REVERSED | 记录退给消费者的实际退款额 |
| REFUND_REVENUE_REVERSED | 退款成功后冲回对应成功核销的商家毛应收 |
| SERVICE_FEE_REFUNDED | 退款成功后返还对应原核销服务费 |

账本同时携带收支方向和事件类型；聚合时使用现有服务中的口径，不能只按金额符号把全部事件直接求和。消费者退款流水不能再作为商家收入扣一次。

未核销券没有确认核销收入和服务费，退款不产生这两项冲回。已核销券退款沿用原核销快照冲回收入并返还原服务费，不使用当前商品价或新费率重新算。普通单次券示例：退用户85元，商家毛应收冲回90元、返还服务费4.50元，商家结算净影响为−85.50元。

次卡退款可退金额、审批资格、已使用部分处理受退款服务规则控制，不直接把整张售价当成可退金额。详见退款专题。已结算后的退款通过后续负向调整处理，不覆盖历史结算批次。

## 8. 数据与排查顺序

| 表 | 核对内容 |
|---|---|
| voucher_product | 当前单份售价、两方补贴及版本 |
| voucher_order | 创建时总价、数量、补贴合计、实付 |
| user_voucher | 每张券的售价、补贴、实付与使用次数快照 |
| commission_rule | 门店/平台默认费率及生效时间 |
| voucher_redemption | 当次分摊、费率、服务费、净收入快照 |
| fund_ledger_entry | 幂等事件、收支方向、收入和费用分录 |
| voucher_refund / voucher_refund_item | 批准退款额、收入冲回和服务费返还 |
| operation_audit_log | 平台补贴和其他管理操作记录 |

排查先看订单快照，再看用户券、核销快照、当时费率和账本。不要用商品当前补贴解释历史订单，不要用当前费率重算历史核销。

## 9. 验证与边界

2026-09-13 已验证补贴数量汇总、超额/负值校验、零值取消、商家不能覆盖平台补贴、订单快照不变、平台接口400/401/409、版本递增及实际 OpenAPI。相关后端20项单元测试和隔离 MySQL 运行时测试通过；三端相关测试与类型检查通过，管理端构建通过。微信开发者工具及真机中的补贴新布局尚未实测。

当前没有独立的活动预算、补贴资金池、额外经营奖励、多币种或计费版本字段。真实支付通道费用不能凭空加入现有公式；若后续接入，应明确承担方和账本科目。手续费、佣金和活动优惠均以本文及当前实现为准。
